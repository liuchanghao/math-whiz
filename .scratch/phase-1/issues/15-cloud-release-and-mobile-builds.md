# 15 — 云效发布与移动端内部构建

**What to build:** 将已完成的一期系统交付到现有阿里云资源：云效自动检查、测试、构建并推送明确版本镜像，经人工批准后部署到 ECS 并连接内网 RDS；同时使用 EAS Build 产出可在手机和平板上安装的内部测试版本。

**Blocked by:** 14 — 生产容器与运维基础.

**Status:** ready-for-agent

- [ ] 部署前核实 ECS 操作系统和 RDS MySQL 实际版本；若 RDS 不是目标 MySQL 8.4，在无业务数据时完成兼容性验证与升级或重建决策。
- [ ] ECS 与 RDS 位于同地域同 VPC，API 使用内网地址和最小权限 RDS 账号连接，RDS 不对公网开放。
- [ ] 云效 Flow 从 Gitee 获取代码，执行冻结安装、格式/Lint、类型检查、单元测试、MySQL 集成测试、后台 E2E、Prisma 检查和生产构建。
- [ ] 只有通过全部检查的 `main` 版本标签才能将带 Git 提交号的管理后台/API 镜像推送到同地域 ACR 企业基础版。
- [ ] 生产部署有明确人工批准节点，普通代码推送不会直接改变线上容器。
- [ ] 部署按“拉取明确镜像 → 执行已审查迁移 → 更新容器 → 存活/就绪检查”执行，失败时可回退到上一应用镜像。
- [ ] 已备案根域名的管理和 API 子域名通过 HTTPS 可访问，裸域名仍保留；应用端口和 RDS 均不直接暴露。
- [ ] 线上系统经验证可完成管理员录题与奖品配置、会员登录、10 题作答、报告和满分获奖闭环。
- [ ] EAS Build 使用明确的内部测试配置产出 Android/iOS 安装包，构建过程不将 API 密钥或服务端凭据嵌入客户端。
- [ ] 内部构建分别在真实手机、平板竖屏和平板横屏完成基本冒烟验收。
- [ ] 公开上架之前不自动提交应用市场；清理内部测试会员数据和完成合规材料仍作为后续人工检查点。
