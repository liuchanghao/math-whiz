# 14 — 生产容器与运维基础

**What to build:** 将已验证的管理后台和 API 制作为可追溯生产镜像，并提供单 ECS 上由 Nginx 统一 HTTPS 入口的 Docker Compose 运行方案，包含安全配置、Prisma 迁移、日志、健康检查和可回退发布步骤。

**Blocked by:** 12 — 会员管理与只读答题记录; 13 — 平板优先与手机适配验收.

**Status:** ready-for-agent

- [ ] 管理后台和 API 分别生成非 root、多阶段、尽量精简的生产镜像，并可由 CI 在不注入生产密钥的情况下构建。
- [ ] Docker Compose 只编排 Nginx、管理后台和 API，不包含 MySQL、Redis、Worker 或 OSS。
- [ ] Nginx 为管理后台和 API 提供不同子域名的 HTTPS 反向代理，应用端口不直接向公网暴露。
- [ ] Nginx 配置登录类路径的 IP 频率限制，并保留可轮转的访问和错误日志。
- [ ] API 输出包含时间、级别、请求编号、路径、状态、耗时、主体内部编号和错误码的结构化 JSON 日志，不包含敏感数据。
- [ ] Docker 日志配置文件大小与保留数量轮转，防止单 ECS 磁盘被日志填满。
- [ ] 生产变量通过 ECS 受限配置注入，数据库凭据、会话密钥和管理员初始化密钥相互独立，不进入 Git、镜像或日志。
- [ ] 生产发布只执行已提交的 `prisma migrate deploy`，禁止 `db push`，并在风险迁移前要求确认 RDS 备份可恢复。
- [ ] 发布流程使用明确 Git 提交号镜像、执行存活/就绪检查并保留上一版镜像的回退步骤，不以 `latest` 作为唯一版本。
- [ ] CI 可构建两个生产镜像、验证 Compose/Nginx 配置并运行生产应用健康检查。
