# 数学小达人一期功能规格书

> 状态：Ready for agent（可拆分开发任务）  
> 基线日期：2026-08-21  
> 适用范围：一期本地开发、线上生产部署与内部测试

## Problem Statement

项目需要一个可统一开发、测试和部署的数学答题系统。家长或监护人的手机号是唯一会员标识，孩子使用已登录的移动应用选择年级、完成数学题作答并查看结果。移动应用绝大部分安装在平板电脑上，也会安装在手机上，必须在不同尺寸和方向下保持可读、可点击且不丢失作答状态。系统管理员需要通过管理后台维护会员、年级、知识点、数学题和实物奖品，并只读查看答题记录。

一期只有少量内部测试会员，不开放移动应用注册、短信验证码登录、忘记密码或手机号变更。一期必须先建立完整的“题库管理 → 选择年级 → 10 题作答 → 自动评分 → 答题报告 → 满分展示奖品”业务闭环，并能部署到现有的阿里云生产基础设施。

## Solution

建设一个 pnpm Workspaces + Turborepo 单仓库，统一管理三个独立应用：

- Next.js 管理后台，供唯一系统管理员维护业务数据。
- Next.js + Node.js 22 独立 API，以模块化单体结构同时服务管理后台和移动应用。
- Expo + React Native 移动应用，作为唯一需要上架 Android/iOS 应用市场的客户端；采用平板优先、手机兼容的自适应界面。

数据保存在 MySQL，由 Prisma ORM 7 和 Prisma Migrate 管理。共享 Zod 4 契约统一 API 请求、响应、业务枚举和 TypeScript 类型。答题轮次由服务端持有，逐题保存、可中断恢复，在第 10 题提交后原子地完成评分、报告、错题和获奖结算。

## User Stories

### 会员身份与会话

1. As a 会员, I want 使用手机号和密码登录移动应用, so that 孩子可以开始答题。
2. As a 会员, I want 在手机号格式不正确时看到明确提示, so that 我可以修正输入。
3. As a 会员, I want 在账号或密码错误时看到统一提示, so that 系统不会泄露手机号是否存在。
4. As a 会员, I want 登录后保持会话, so that 重新打开移动应用时不必每次输入密码。
5. As a 会员, I want 在新设备登录后使旧设备会话失效, so that 一期只有一个有效设备会话。
6. As a 会员, I want 主动退出登录, so that 当前设备不再保留有效会话。
7. As a 会员, I want 输入原密码和两次新密码修改密码, so that 我可以更新账号凭据。
8. As a 会员, I want 修改密码后所有会话失效, so that 我必须使用新密码重新登录。
9. As a 被停用会员, I want 无法新建或继续会话, so that 账号停用立即生效。
10. As a 项目维护者, I want 直接在数据库中初始化少量会员, so that 一期无需开发注册功能也能测试。

### 年级与答题轮次

11. As a 会员, I want 查看可开始答题的小学一至六年级, so that 我可以选择本轮难度范围。
12. As a 会员, I want 只看到已满足题量和奖品条件的年级, so that 不会启动无法完成或无法发奖的轮次。
13. As a 会员, I want 选择年级后开始一个包含 10 道数学题的答题轮次, so that 我可以完成一次标准作答。
14. As a 会员, I want 同一轮中不出现重复数学题, so that 每轮都有 10 道不同的题。
15. As a 会员, I want 系统优先选择我没有答过的数学题, so that 可以尽量练习新内容。
16. As a 会员, I want 新题不足时复用以前答过但最久未出现的题, so that 题库可在一期持续使用。
17. As a 会员, I want 每轮默认包含 4 道简单题、4 道中等题和 2 道困难题, so that 作答内容有基本难度梯度。
18. As a 会员, I want 某个难度题量不足时仍能由其他难度补足 10 题, so that 可用题量充足时轮次不会被阻断。
19. As a 会员, I want 同一时间只有一个进行中的答题轮次, so that 答题状态不会分叉。
20. As a 会员, I want 重新打开移动应用后恢复已有轮次的固定题目和进度, so that 我可以继续作答。
21. As a 会员, I want 主动放弃进行中的答题轮次, so that 我可以结束不再继续的作答。
22. As a 会员, I want 超过 7 天未完成的轮次不再恢复, so that 过期作答不会长期占用进行中状态。
23. As a 会员, I want 已放弃轮次不计分、不生成报告也不获得奖品, so that 只有完成的 10 题轮次才进入正式记录。

### 数学题作答与判分

24. As a 会员, I want 作答单选题, so that 我可以从纯文字选项中选择一个答案。
25. As a 会员, I want 作答判断题, so that 我可以选择正确或错误。
26. As a 会员, I want 作答数字填空题, so that 我可以输入整数、小数或分数答案。
27. As a 会员, I want 使用专用数学键盘作答算式输入题, so that 我可以输入数字、运算符和比较符号。
28. As a 会员, I want 在按数位对齐的结构化输入格中作答竖式计算题, so that 竖式过程可以正确展示和保存。
29. As a 会员, I want 数学键盘提供数字、四则运算、比较符号、小数点、删除、清空和确认, so that 不需要依赖系统通用文字键盘。
30. As a 会员, I want 通过专用控件输入分数和括号, so that 复合算式有明确的结构。
31. As a 会员, I want `0.5`、`0.50` 和 `1/2` 在默认数值判分下视为相等, so that 数学上等价的答案不会被误判。
32. As a 会员, I want 数学题要求指定格式时按该格式判分, so that 格式本身属于考查目标的题可以正确评分。
33. As a 会员, I want 算式输入与多个可接受答案中的任意一个匹配时判定正确, so that 不同的合理列式都可以通过。
34. As a 会员, I want 竖式计算题一期只按最终结果计 10 分或 0 分, so that 评分规则简单一致。
35. As a 会员, I want 每道题提交后保存答案但不立即显示对错, so that 在完成 10 题之前不会提前获得正确答案。
36. As a 会员, I want 网络重试不会重复提交同一道答案, so that 作答进度和评分保持一致。
37. As a 会员, I want 完成第 10 题后获得统一评分, so that 每道题按 10 分计算出 100 分总分。

### 报告、错题、收藏与获奖

38. As a 会员, I want 轮次完成后查看总分, so that 我知道本轮作答结果。
39. As a 会员, I want 在答题报告中查看每道错题、自己的答案和正确答案, so that 可以复盘错误。
40. As a 会员, I want 在答题报告中查看可用的答案解析, so that 可以理解解题过程。
41. As a 会员, I want 查看每一次已完成的答题报告, so that 可以回顾历史作答。
42. As a 会员, I want 系统在完成轮次后自动记录答错的数学题, so that 我可以在错题本中查看它们。
43. As a 会员, I want 对数学题进行收藏或取消收藏, so that 我可以保留想再次查看的题。
44. As a 会员, I want 查看已收藏的数学题, so that 可以集中回顾。
45. As a 会员, I want 在每次获得 100 分后看到当前实物奖品信息, so that 我知道本轮获得了什么奖品。
46. As a 会员, I want 同一奖品在多个满分轮次中分别生成获奖记录, so that “每次满分都获奖”的规则不受历史获奖影响。
47. As a 会员, I want 查看历史获奖记录和线下领取说明, so that 可以在弹窗关闭后再次查看奖品信息。

### 系统管理员与后台

48. As a 系统管理员, I want 使用独立管理员用户名和密码登录管理后台, so that 管理权限不与会员身份混用。
49. As a 系统管理员, I want 登录后通过安全 Cookie 保持后台会话, so that 管理凭据不暴露给客户端脚本。
50. As a 系统管理员, I want 查看会员列表和基本状态, so that 可以管理现有会员。
51. As a 系统管理员, I want 按手机号查找会员, so that 可以定位具体测试账号。
52. As a 系统管理员, I want 启用或停用会员, so that 可以控制会员是否允许登录。
53. As a 系统管理员, I want 查看和维护小学一至六年级的名称、顺序和启用状态, so that 可以控制移动应用的年级入口。
54. As a 系统管理员, I want 创建、修改、启用和停用知识点并关联年级, so that 数学题可以精确分类。
55. As a 系统管理员, I want 创建纯文字数学题, so that 题库不依赖图片或文件存储。
56. As a 系统管理员, I want 为数学题选择题型、难度、多个年级和多个知识点, so that 题目可以正确参与抽题和分类。
57. As a 系统管理员, I want 为一道数学题指定一个主要知识点, so that 报告和后台统计有明确主分类。
58. As a 系统管理员, I want 为数学题配置正确答案和可选答案解析, so that 系统可以自动判分并在报告中解释。
59. As a 系统管理员, I want 将数学题保存为草稿、启用或停用, so that 只有已启用题目参与抽题。
60. As a 系统管理员, I want 修改尚未进入任何轮次的数学题, so that 可以在投入使用前修正内容。
61. As a 系统管理员, I want 无法修改已被答题轮次使用的题干、选项和正确答案, so that 历史答题报告不会被后台改写。
62. As a 系统管理员, I want 停用有错的历史题并创建新题, so that 新轮次不再抽取旧题。
63. As a 系统管理员, I want 查看答题记录列表和详情, so that 可以核对会员的完成情况和答案。
64. As a 系统管理员, I want 答题记录没有修改或删除入口, so that 原始作答事实不会被管理后台更改。
65. As a 系统管理员, I want 创建和维护纯文字实物奖品信息, so that 移动应用可以展示奖品名称、说明和线下领取说明。
66. As a 系统管理员, I want 设置奖品的启用状态和适用年级, so that 无效奖品不能被设为当前奖品。
67. As a 系统管理员, I want 为每个年级设置唯一当前奖品, so that 满分结算有唯一可展示奖品。
68. As a 系统管理员, I want 在年级题量少于 10 或没有当前奖品时无法开放该年级, so that 不会出现无法完成或无奖品的轮次。
69. As a 系统管理员, I want 关键后台操作自动形成不可修改的审计记录, so that 会员状态、题库和奖品变更可以追溯。

### 运维与发布

70. As a 开发者, I want 在同一仓库中统一管理管理后台、API、移动应用和共享契约, so that 三个应用的变更可以协同交付。
71. As a 开发者, I want 本地直接使用 Node.js 和 MySQL 运行项目而不使用 Docker, so that 本地调试保持简单。
72. As a 开发者, I want 使用独立测试 MySQL 执行集成测试, so that 测试不会连接本地开发数据或生产 RDS。
73. As a 发布者, I want 管理后台和 API 以 Git 提交号标记的镜像推送到 ACR, so that 每次生产部署都能定位到明确代码版本。
74. As a 发布者, I want 生产部署必须经过人工确认, so that 代码推送不会自动改变线上系统。
75. As a 发布者, I want 部署时先应用已审查的 Prisma 迁移再更新容器, so that 应用与数据库结构保持兼容。
76. As a 发布者, I want 部署后运行存活和就绪检查并保留上一版镜像, so that 失败时可以明确回退。
77. As a 运维者, I want API 输出不含密码、令牌、完整手机号或完整作答内容的结构化日志, so that 可排查错误且不会在日志中泄露敏感数据。
78. As a 运维者, I want RDS 只通过同 VPC 内网向 ECS 开放, so that 数据库不暴露在公网。
79. As a 发布者, I want 使用 EAS Build 生成移动应用安装包且手动触发生产构建与商店提交, so that 移动版本不会随普通代码推送自动发布。

### 平板与手机适配

80. As a 平板用户, I want 在横屏和竖屏下都能清晰查看题干、作答区和进度, so that 我可以按当前平板使用方式答题。
81. As a 手机用户, I want 在紧凑屏幕上使用单列布局完成全部题型, so that 数学键盘、选项和报告不会被遮挡或挤压到无法操作。
82. As a 会员, I want 屏幕旋转或窗口尺寸变化后保留当前轮次、当前题和已输入答案, so that 设备姿态变化不会中断作答。

## Implementation Decisions

### 1. 交付边界

- 一期交付三个可独立运行的应用：管理后台、API 和移动应用。
- 管理后台和 API 部署到线上生产环境；移动应用产出可安装的 Android/iOS 构建，商店公开发布不是一期验收前置条件。
- 一期不开发自助注册界面或会员创建 API。项目维护者直接初始化 1–2 个测试会员，数据库只写入密码哈希。
- 一期只识别会员，不建立学生账号、孩子档案、家长角色或家长端。家长或监护人是手机号的现实持有者，孩子使用已登录移动应用答题。

### 2. 仓库与模块边界

- 使用 Node.js `22.x`、pnpm Workspaces 和 Turborepo，仓库只保留 pnpm 锁文件。
- 管理后台使用 Next.js；API 是独立 Next.js 应用；移动应用使用 Expo、React Native 和 TypeScript。
- API 内部是模块化单体，分为 `identity`、`catalog`、`practice`、`reporting`、`rewards` 和 `audit` 业务模块。
- 共享包只承载 Zod 契约、TypeScript 类型、通用配置和无业务状态的工具；业务实现只存在于 API。
- 一期 API 不依赖 Redis、Worker、队列、OSS 或其他对象存储。

### 3. 用户界面范围

移动应用包含以下用户界面：

- 启动与会话恢复。
- 手机号 + 密码登录。
- 年级选择与进行中轮次恢复。
- 五种题型的逐题作答、进度展示和主动放弃。
- 数学键盘与竖式结构化输入。
- 轮次结果、满分奖品弹层和答题报告详情。
- 历史答题报告、错题本、收藏和获奖记录的基本列表/详情查看。
- 修改密码与退出登录。

移动应用的适配规则：

- 以可用宽度而不是具体设备型号决定布局，不在业务页面中写死平板或手机像素尺寸。
- 手机紧凑宽度使用单列布局，题干、答题区、数学键盘和主操作按阅读顺序竖向排列。
- 平板宽屏可在不降低可读性的前提下使用双区域布局，例如题干/进度与作答/键盘分区；内容区设置合理最大宽度，避免文字在大屏上过度拉伸。
- 平板必须支持横屏和竖屏；手机一期以竖屏为主，旋转后不得丢失作答状态。
- 所有核心按钮和数学键盘键使用不小于 48 个逻辑像素的点击区域，并保留明确的按压反馈。
- 题干、选项、竖式输入格和数学键盘不得依赖绝对定位组成整页；必须适配安全区、系统导航区和软键盘遮挡。
- 屏幕尺寸或方向变化只重排布局，不重建答题轮次，不清空当前未提交输入。

管理后台包含以下用户界面：

- 系统管理员登录与退出。
- 会员列表、详情、手机号查询和启用/停用。
- 年级列表与名称、顺序、启用状态维护。
- 知识点列表、创建、修改、关联年级和启用/停用。
- 数学题列表、创建、详情、允许范围内的修改和启用/停用。
- 答题记录列表与只读详情。
- 奖品列表、创建、修改、启用/停用、适用年级与当前奖品设置。

一期不要求独立仪表盘、复杂统计图表或审计日志管理页面。

### 4. 核心数据模型

- **Member**：内部稳定编号、规范化手机号（唯一）、密码哈希、会员状态、连续登录失败次数、暂停登录截止时间和时间戳。
- **MemberSession**：会员、刷新令牌摘要、过期时间、撤销时间和轮换关系。每个会员只允许一个有效设备会话。
- **Admin** 与 **AdminSession**：与会员完全分离的管理员凭据、状态、登录限制和服务端会话。
- **Grade**：一至六年级的编号、名称、顺序、启用状态和当前奖品关联。
- **KnowledgePoint**：名称、启用状态、时间戳及与年级的多对多关联。
- **Question**：题型、纯文字题干、可选解析、难度、状态、判分配置、是否已被使用和时间戳。
- **QuestionOption**：单选题的纯文字选项、显示顺序和稳定编号。正确性只向管理接口和服务端判分暴露。
- **QuestionGrade**：数学题与年级的多对多关联。
- **QuestionKnowledgePoint**：数学题与知识点的多对多关联，包含唯一主要知识点标记。
- **Round**：会员、年级、轮次状态、得分、开始、过期、完成和放弃时间。数据库约束与事务逻辑共同保证每个会员最多一个进行中轮次。
- **RoundQuestion**：轮次内固定的数学题、顺序、结构化会员答案、是否正确、得分和作答时间。同一轮次中题目和顺序均唯一。
- **AnswerReport**：与已完成轮次一对一关联的报告摘要，包含总分和生成时间；详细题目从固定轮次题目读取。
- **WrongQuestion**：会员与曾答错数学题的唯一关联，保留首次和最近答错时间。一期不建立“已掌握”状态。
- **FavoriteQuestion**：会员与收藏数学题的唯一关联。
- **Prize**：纯文字名称、说明、线下领取说明、启用状态和适用年级关联。
- **Award**：会员、已完成轮次、奖品、获奖时间，以及获奖时的奖品名称、说明和线下领取说明快照。每个满分轮次只有一条不可修改的获奖记录。
- **IdempotencyRecord**：会员、接口范围、请求幂等编号、请求摘要和已产生结果，用于防止写请求网络重试重复执行。
- **AuditLog**：管理员、操作类型、目标类型与编号、脱敏变更摘要、请求编号和时间。业务接口不提供修改或删除审计记录的能力。

所有业务时间以 UTC 保存，用户界面按中国标准时间展示。手机号一期按中国大陆 11 位移动号码规范化和校验，数据库存储不含空格或分隔符的数字。

### 5. 状态与业务规则

- 会员状态只有“已启用”和“已停用”。停用时撤销全部会话，但不物理删除会员或历史业务数据。
- 数学题状态只有“草稿”、“已启用”和“已停用”。只有已启用题可抽取。
- 数学题一旦进入任何轮次，题干、选项和正确答案不可修改。管理员仍可停用该题；修正内容时必须新建题目。
- 答题轮次状态只有“进行中”、“已完成”和“已放弃”。进行中轮次创建时设置 7 天过期时间。
- API 在查询、恢复或新建轮次时，在事务内将已过期的进行中轮次转为已放弃；一期不使用定时任务。
- 一个年级只有在已启用、关联至少 10 道不同的已启用数学题，且设置了一个适用于该年级的已启用当前奖品时，才向移动应用开放。
- 新建轮次时一次性固定 10 道题和题目顺序。默认按 4 简单、4 中等、2 困难抽取；任一难度不足时，从其他难度的可用题中补齐。
- 每个难度内先从会员未答过的题中随机选择，再按该会员最久未看到的时间补齐已答过的题；任何步骤都不得在同一轮重复选题。
- 会员按轮次题目顺序逐题确认答案。答案首次成功提交后不再修改；同一幂等编号的重试返回首次成功结果。
- 前 9 题提交响应只返回已保存和下一题进度，不返回对错、正确答案或解析。
- 第 10 题提交时锁定答题轮次，在一个 MySQL 事务中保存答案、评分、生成答题报告、更新错题本并在 100 分时创建获奖记录。任一步失败时整个事务回滚。
- 奖品信息可在后台调整，但获奖记录保留结算时的奖品文字快照，保证历史获奖内容稳定。

### 6. 题型与答案契约

- **单选题**：管理员配置至少 2 个纯文字选项和唯一正确选项；会员答案只提交选项编号。
- **判断题**：正确答案是布尔值；移动应用展示“正确/错误”固定选项。
- **数字填空题**：答案保留原始输入，并按题目配置执行数学值等价或指定格式匹配。等价判分只接受安全的数值、小数和分数语法。
- **算式输入题**：移动应用提交由专用数学键盘生成的结构化表达式及用于展示的标准文本；API 使用安全解析和规范化逻辑与多个可接受答案匹配，绝不执行输入内容。
- **竖式计算题**：移动应用提交按行、列和数位组织的过程格与最终结果；API 保存完整结构，一期只比较最终结果。
- 题干、选项、答案解析和奖品字段只接受纯文字、换行和常用数学 Unicode 符号；不解析 HTML、Markdown 或 LaTeX，也不接受图片。

### 7. API 边界

API 使用 REST + JSON，所有路径按移动应用和管理后台分离。一期至少提供以下公开接口边界。

移动应用：

- `POST /api/v1/mobile/auth/login`：手机号 + 密码登录。
- `POST /api/v1/mobile/auth/refresh`：轮换刷新令牌并发放新访问令牌。
- `POST /api/v1/mobile/auth/logout`：撤销当前会话。
- `POST /api/v1/mobile/auth/change-password`：验证原密码并修改密码。
- `GET /api/v1/mobile/me`：获取当前会员最小账号信息。
- `GET /api/v1/mobile/grades`：获取当前可开放答题的年级。
- `GET /api/v1/mobile/rounds/active`：获取唯一进行中轮次，无数据时返回 `data: null`。
- `POST /api/v1/mobile/rounds`：为指定年级创建轮次并固定 10 道题。
- `GET /api/v1/mobile/rounds/{roundId}`：恢复轮次题目、已答进度和当前题。
- `POST /api/v1/mobile/rounds/{roundId}/answers`：顺序提交当前题答案，第 10 题时完成结算。
- `POST /api/v1/mobile/rounds/{roundId}/abandon`：主动放弃进行中轮次。
- `GET /api/v1/mobile/reports`：分页获取已完成答题报告。
- `GET /api/v1/mobile/reports/{reportId}`：获取报告总分、逐题结果、正确答案和解析。
- `GET /api/v1/mobile/wrong-questions`：分页获取错题本。
- `GET /api/v1/mobile/favorites`：分页获取收藏数学题。
- `PUT /api/v1/mobile/favorites/{questionId}`：幂等收藏数学题。
- `DELETE /api/v1/mobile/favorites/{questionId}`：幂等取消收藏。
- `GET /api/v1/mobile/awards`：分页获取获奖记录和线下领取说明。

管理后台：

- `POST /api/v1/admin/auth/login`、`POST /api/v1/admin/auth/logout`、`GET /api/v1/admin/me`：管理员会话。
- `GET /api/v1/admin/members`、`GET /api/v1/admin/members/{memberId}`：查询会员。
- `POST /api/v1/admin/members/{memberId}/enable`、`POST /api/v1/admin/members/{memberId}/disable`：变更会员状态。
- `GET /api/v1/admin/grades`、`PATCH /api/v1/admin/grades/{gradeId}`：查看和维护预置年级。
- `GET/POST /api/v1/admin/knowledge-points`、`GET/PATCH /api/v1/admin/knowledge-points/{knowledgePointId}`：知识点管理。
- `GET/POST /api/v1/admin/questions`、`GET/PATCH /api/v1/admin/questions/{questionId}`：数学题查询、创建和受限修改。
- `POST /api/v1/admin/questions/{questionId}/enable`、`POST /api/v1/admin/questions/{questionId}/disable`：变更题目状态。
- `GET /api/v1/admin/answer-records`、`GET /api/v1/admin/answer-records/{roundId}`：只读查询答题记录。
- `GET/POST /api/v1/admin/prizes`、`GET/PATCH /api/v1/admin/prizes/{prizeId}`：奖品查询、创建和修改。
- `POST /api/v1/admin/prizes/{prizeId}/enable`、`POST /api/v1/admin/prizes/{prizeId}/disable`：变更奖品状态。
- `PUT /api/v1/admin/grades/{gradeId}/current-prize`：设置年级的唯一当前奖品。

路径名称是一期契约基线；实现时如需纯命名调整，必须在编写客户端前同步修改共享契约和本规格。

### 8. API 响应与错误

- 所有成功操作返回 HTTP 200，响应体固定为 `status`、`message`、`data` 三个顶层字段，且 `status` 为 `200`。
- 无业务数据的成功操作返回 `data: null`。
- 分页数据固定为 `items`、`page`、`pageSize`、`total`。
- 参数错误、未登录、无权限、资源不存在、状态冲突和服务异常分别使用 HTTP/响应体状态 `400`、`401`、`403`、`404`、`409` 和 `500`。
- 错误响应在 `data.errorCode` 中返回稳定错误码，字段校验错误可在 `data.fields` 指出字段。客户端不根据中文 `message` 分支。
- 核心业务错误码至少覆盖：手机号格式错误、登录凭据错误、登录已暂停、会员已停用、已存在进行中轮次、年级未开放、轮次状态冲突、答案顺序错误、幂等编号内容冲突、题目已锁定和当前奖品不可用。

### 9. 认证、安全与审计

- 手机号和密码在 API 端必须再次校验，不信任客户端校验。
- 密码使用成熟的自适应密码哈希算法，数据库、日志和响应中绝不保存或返回明文。
- 本地测试账号可使用初始密码 `123456`；线上每个测试账号必须使用不同的随机强密码。
- 移动应用使用短期访问令牌与可轮换刷新令牌，并存放在操作系统安全存储中；服务端只保存可撤销的令牌摘要。
- 管理后台使用 `Secure`、`HttpOnly`、`SameSite` Cookie，受保护写操作进行 CSRF 防护。
- 管理员由一次性初始化流程创建，使用随机强密码；一期只有一种拥有全部权限的管理员角色，不实现 RBAC。
- Nginx 按 IP 限制登录速率。API 使用 MySQL 记录失败计数：会员连续失败 5 次后暂停登录 15 分钟，管理员使用更严格的独立配置。
- 关键管理员操作与业务数据变更在同一事务中写入审计记录。审计摘要不包含密码、令牌或完整手机号。
- 一期只采集手机号和认证数据，以及答题、报告、错题、收藏和获奖数据；不采集孩子姓名、性别、出生日期、学校班级、身份证、精确位置或通讯录。

### 10. 生产部署与运行

- 本地开发直接运行 Node.js、管理后台、API、移动应用和本地 MySQL，不使用 Docker 作为本地运行方式。
- 线上使用一台中国大陆阿里云 ECS 运行 Nginx、管理后台和 API 容器，接受发布时短暂停机。
- RDS MySQL 与 ECS 位于同地域同 VPC，只允许 ECS 通过内网访问；一期不开放 RDS 公网。
- Nginx 统一提供 HTTPS 和反向代理。管理后台使用 `admin.<根域名>`，API 使用 `api.<根域名>`，裸域名预留。
- 管理后台和 API 镜像保存在同地域 ACR 企业基础版，使用 Git 提交号标记且不依赖 `latest`。
- Gitee + 阿里云云效 Flow 执行检查、测试、构建与推送镜像；生产部署需人工批准。
- 生产发布顺序是检查/测试、构建、推送 ACR、人工确认、ECS 拉取、`prisma migrate deploy`、更新容器、健康检查。
- API 提供存活和就绪检查；就绪检查验证 RDS 可用性，但不返回敏感配置。
- API 向标准输出写入结构化 JSON 日志，包含时间、级别、请求编号、路径、状态、耗时、主体内部编号和错误码；Docker 和 Nginx 配置日志轮转。
- 生产环境变量保存在 ECS 受限配置中，不进入 Git、镜像或日志；API 使用最小权限 RDS 账号。

### 11. 共享契约与迁移

- Zod 4 契约按认证、会员、年级/题目、轮次、报告和奖品领域分区。
- 管理后台、移动应用和 API 只通过共享公开契约交换数据，不共享 Prisma 数据库模型。
- 不生成 OpenAPI 文档且不提供 Swagger UI；Zod 契约、契约测试和本规格是一期接口依据。
- Prisma schema 和迁移历史提交到仓库。本地只使用 `prisma migrate dev`，线上只使用 `prisma migrate deploy`，生产禁止 `db push`。

## Testing Decisions

### 测试缝合线

- 核心业务的最高优先级测试缝合线是“公开 REST API + 真实测试 MySQL”。测试通过 HTTP 请求验证统一响应、数据持久化、事务和权限，不断言内部函数调用次数。
- 表达式解析、数学等价判断、竖式最终结果判定和抽题算法是为数不多的纯领域规则缝合线，使用表格化单元测试覆盖边界值和随机性约束。
- 共享 Zod 契约使用契约测试验证成功、错误、空数据和分页包装，防止三个应用对响应结构理解不一致。
- 管理后台和移动应用的组件测试只验证用户可见状态与交互；关键流程再使用少量端到端测试覆盖。

### API 与数据库集成测试

- 会员与管理员身份、登录入口和会话不能交叉使用。
- 手机号唯一、格式校验、密码错误统一提示、5 次失败暂停 15 分钟、新设备登录撤销旧会话。
- 修改密码必须验证原密码与两次新密码一致，成功后撤销所有会话。
- 停用会员不能登录且现有会话失效，历史报告和获奖数据不被删除。
- 年级少于 10 道已启用不同数学题或无当前奖品时不向移动应用开放。
- 抽题固定 10 道不重复题、默认 4/4/2 难度比例、难度不足补齐、优先未答题并按最久未出现复用旧题。
- 并发新建请求不能为同一会员生成多个进行中轮次。
- 中断后恢复相同题目、顺序和已答进度；主动放弃与 7 天过期均进入已放弃，且不产生报告、错题或奖品。
- 前 9 题响应不含对错、正确答案或解析。
- 第 10 题提交成功后轮次、报告、错题和可选获奖数据全部完成；任一环节注入失败时不得留下部分结算结果。
- 同一答案幂等编号重试返回同一结果；同一编号搭配不同请求内容返回冲突。
- 每个 100 分轮次只生成一条获奖记录，不同满分轮次可重复获得同一奖品，历史奖品文字快照不随奖品后续修改而改变。
- 已进入轮次的数学题不能修改题干、选项和正确答案；停用后不再进入新轮次。
- 答题记录管理接口不存在修改或删除能力。
- 管理员关键写操作成功时同步产生审计记录，失败时业务变更和审计记录一起回滚。
- 所有 API 的统一成功、错误、空数据和分页响应符合共享 Zod 契约。

### 纯领域规则单元测试

- 整数、负数、小数、可约分分数、分母为零、非法符号和超长输入。
- 等价算式、多个可接受答案、运算优先级、括号、比较关系和不安全/不支持语法拒绝。
- 竖式过程结构往返保真，以及只按最终结果判定正确性。
- 各难度题量充足、单一难度不足、多个难度不足、新题不足和总题量恰好 10 道时的抽题结果。

### 管理后台与移动应用测试

- 管理后台使用 Vitest 测试表单校验和可见状态，使用 Playwright 覆盖管理员登录、创建并启用数学题、配置年级当前奖品、停用会员和只读查看答题记录。
- 移动应用使用 Jest + React Native Testing Library 测试登录、题型组件、数学键盘、轮次恢复、报告和奖品弹层的用户可见行为。
- Maestro 覆盖两条关键移动流程：登录后完成非满分轮次并查看报告；登录后完成满分轮次并看到奖品。
- 每个核心移动页面至少在手机紧凑竖屏、平板竖屏和平板横屏三类可用宽度下执行布局验证。
- Maestro 的关键答题流程至少分别在一个手机模拟器和一个平板模拟器执行；发布前在实际手机和平板上进行基本冒烟验证。
- 旋转测试必须验证当前轮次编号、当前题、已答进度和尚未提交的当前输入均未丢失。

### 测试先例

仓库当前只有架构文档，没有现有代码或测试先例可复用。首个踪迹式开发任务应建立上述 API 集成测试基线，后续功能不得各自建立相互竞争的测试入口。

### CI 验收门槛

- 冻结锁文件安装。
- 格式、Lint 和 TypeScript 类型检查。
- API、共享契约和管理后台单元测试。
- 使用独立 MySQL 的 API 集成测试。
- 管理后台 Playwright 关键流程。
- Prisma schema 验证、迁移检查和生成客户端检查。
- 管理后台和 API 生产构建。
- 任一门槛失败时不生成可部署生产镜像。

## Out of Scope

- 一期移动应用自助注册、短信验证码登录、忘记密码、密码找回和手机号变更。
- 家长或监护人短信注册、监护同意记录、账号注销流程及二期隐私生命周期功能。
- 学生账号、孩子档案、多孩子切换、家长角色、家长端或家长专区。
- 固定试卷、试卷管理、考试监考、排名、积分、虚拟奖品和付费。
- 图片题目、奖品图片、文件上传、OSS、HTML、Markdown 或 LaTeX 内容。
- 拍照搜题、AI 辅导、语音、完整离线答题、实时对战和社交功能。
- 竖式过程部分给分、错题“已掌握”生命周期、复杂学习统计或图表。
- 奖品库存、价格、订单、支付、收货地址、物流、领取状态或线上履约。
- 多管理员角色、RBAC、答题记录修改或删除。
- 推送通知、广告 SDK、用户画像或第三方行为分析 SDK。
- Redis、后台 Worker、任务队列、微服务拆分、Kubernetes、负载均衡、多机高可用和独立云端测试环境。
- OpenAPI 文档和 Swagger UI。
- 裸域名官网或应用下载引导页的建设。

## Further Notes

- 本规格使用项目 `CONTEXT.md` 中的领域语言，并受现有 ADR 约束；与本规格冲突时，应先明确修改已确认的架构决策。
- 仓库当前未配置外部问题跟踪器；根据用户的明确要求，本规格首先以仓库 Markdown 文档作为发布产物。
- 开始实施前必须核实现有 RDS MySQL 实际版本和 ECS 操作系统。若 RDS 不是 MySQL 8.4，应在尚无业务数据时先完成兼容性验证与升级或重建决策。
- 本地 MySQL 当前客户端报告为 9.7.0，实施时应与目标 RDS MySQL 8.4 主版本对齐，避免迁移在本地通过但在生产失败。
- 移动应用面向孩子使用。公开上架前，用户协议、隐私政策、儿童信息处理和应用市场材料需另行进行法务/合规确认。
