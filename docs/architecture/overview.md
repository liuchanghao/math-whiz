# 数学小达人架构概览

> 状态：一期架构基线已确认（2026-08-21）。后续调整应同步更新本文、领域语言和相关 ADR。

## 系统边界

项目使用单仓库统一管理三个独立应用：

- `apps/admin`：Next.js 管理后台，供系统管理员管理会员、年级、知识点、数学题、答题记录和奖品。
- `apps/mobile`：Expo + React Native 移动应用，发布到应用市场；以平板电脑为主要使用终端，同时适配手机，会员登录后选择年级并答题。
- `apps/api`：独立 Next.js API，使用 Node.js，同时向移动应用和管理后台提供业务接口。
- `packages/*`：共享类型、接口契约、校验规则和工程配置；不承载独立部署的业务服务。

## 技术基线

- Node.js `22.x`
- pnpm Workspaces + Turborepo，仓库只保留 pnpm 锁文件
- API 使用独立的 Next.js 应用，并采用模块化单体结构
- 管理后台使用 Next.js
- 移动应用使用 Expo + React Native + TypeScript
- 移动界面采用平板优先的自适应布局：平板支持横屏和竖屏，手机使用紧凑单列布局，旋转和尺寸变化不得丢失当前作答状态
- 数据库目标版本为阿里云 RDS MySQL 8.4 LTS；实施前核实现有实例版本
- API 使用 Prisma ORM 7 访问 MySQL，并使用 Prisma Migrate 管理数据库迁移
- 一期不依赖 Redis；出现短信验证码、集中限流或任务队列等明确需求后再评估引入
- 一期题目与奖品均为纯文字内容，不上传图片或文件，因此不依赖 OSS 等对象存储服务
- 不生成 OpenAPI 文档，不提供 Swagger UI；共享契约代码作为接口结构的来源

## API 与共享契约

- API 使用 REST + JSON，并以 `/api/v1/mobile/*` 和 `/api/v1/admin/*` 区分移动应用与管理后台接口。
- `packages/contracts` 使用 Zod 4 定义请求、响应、业务枚举和共享 TypeScript 类型。
- 移动应用、管理后台和 API 共享契约定义，但业务实现只存在于 API。
- `packages/contracts` 按 `auth`、`members`、`questions`、`rounds`、`reports` 和 `prizes` 分区。
- 不生成 OpenAPI 文档或 Swagger UI，Zod 契约和测试是接口结构的来源。

## 数据访问与迁移

- Prisma schema 和迁移历史提交到仓库。
- 本地使用 `prisma migrate dev` 创建和验证迁移。
- 线上只使用 `prisma migrate deploy` 应用已经提交的迁移，禁止使用 `db push`。
- 发布前审查生成的 SQL，风险迁移执行前确认 RDS 备份可恢复。

## API 业务模块

- `identity`：会员、系统管理员、认证与会话。
- `catalog`：年级、知识点和数学题。
- `practice`：抽题、答题轮次与判分。
- `reporting`：答题报告、错题本与收藏。
- `rewards`：奖品、年级当前奖品与获奖记录。
- `audit`：不可修改的系统管理员关键操作审计记录。

## API 响应约定

- JSON 响应统一包含 `status`、`message` 和 `data`。
- 只有响应体中的 `status: 200` 表示业务处理成功，成功接口不使用 `201` 或 `204` 作为业务成功值。
- 成功响应示例：

```json
{
  "status": 200,
  "message": "xxx",
  "data": {
    "name": "小明"
  }
}
```

- 只有 HTTP 状态和响应体 `status` 都为 `200` 才表示成功；所有成功操作，包括创建、修改和删除，都返回 HTTP 200，不使用 201 或 204。
- 参数错误、未登录、无权限、资源不存在、状态冲突和服务异常分别使用 HTTP/响应体状态 `400`、`401`、`403`、`404`、`409` 和 `500`。
- 错误响应保持相同三个顶级字段，`data.errorCode` 提供稳定的机器可读错误码，`data.fields` 在字段错误时指出相关字段；客户端不得依赖中文 `message` 判断错误类型。
- 成功但没有业务数据时固定返回 `data: null`，不省略字段，也不以空字符串或不稳定的空对象代替。
- 分页数据固定使用 `data.items`、`data.page`、`data.pageSize` 和 `data.total`。

错误响应示例：

```json
{
  "status": 400,
  "message": "手机号格式不正确",
  "data": {
    "errorCode": "INVALID_PHONE",
    "fields": ["phone"]
  }
}
```

分页响应示例：

```json
{
  "status": 200,
  "message": "查询成功",
  "data": {
    "items": [],
    "page": 1,
    "pageSize": 20,
    "total": 0
  }
}
```

## 一期会员认证

- 移动应用暂不开放自助注册。
- 测试会员由人工直接初始化到数据库，一个手机号唯一标识一个会员。
- 会员使用手机号和密码登录；本地开发账号可使用 `123456`，线上生产账号必须分别使用不同的随机强密码。
- 数据库只保存密码安全哈希，不保存明文密码。
- 同一会员一期只允许一个有效设备会话，新设备登录后旧会话失效。
- 会员在登录状态下通过原密码和两次新密码修改密码，不再输入手机号；修改成功后全部会话失效并要求重新登录。
- 一期不提供忘记密码或密码找回。
- 一期不支持更换手机号；二期接入短信后验证旧、新手机号完成换号，会员内部编号和历史数据保持不变。
- 会员状态为已启用或已停用；停用后全部会话失效且不能登录，但答题报告和获奖记录保留，不物理删除会员。
- 一期完成后直接部署到线上生产环境；应用上架前仅有少量人工初始化的自有账号。

## 二期注册与账号生命周期

- 家长或监护人使用自己的手机号和短信验证码注册会员账号，孩子使用该已登录账号答题；不建立孩子账号或学生档案。
- 注册时家长或监护人确认监护人身份或相应授权，并同意用户协议、隐私政策和儿童信息处理规则；系统记录文本版本、时间和渠道。
- 一期与二期均遵循数据最小化：只保存手机号与认证数据，以及答题记录、报告、错题、收藏和获奖记录；不采集姓名、性别、出生日期、学校班级、身份证、精确位置或通讯录。
- 二期提供应用内注销，并通过短信验证本人手机号；注销后立即撤销会话、删除手机号和认证数据，并删除或匿名化关联业务数据，仅保留法律要求保留的记录和不可回溯个人的聚合统计。

## 身份与会话边界

- 会员和系统管理员使用不同数据表、登录接口和会话类型。
- 系统管理员使用管理员用户名和密码登录管理后台；一期唯一管理员通过一次性初始化脚本创建并使用随机强密码。
- 移动应用使用短期访问令牌和可轮换刷新令牌，并保存到操作系统安全存储。
- 管理后台使用 `Secure`、`HttpOnly`、`SameSite` Cookie 保存会话。
- 登录及全部认证接口只允许通过 HTTPS 访问。

## 一期业务范围

- 系统只建立会员身份：家长或监护人是手机号的现实持有者，孩子使用已登录应用答题；不建立学生账号、孩子档案、家长角色或家长区等独立实体。
- 首发覆盖小学一年级至六年级，只提供数学题内容；会员登录后选择本轮答题年级。
- 数学题可以关联多个年级，并以知识点进行更精确的后台分类；一期移动应用不要求会员选择知识点。
- 管理后台增加知识点管理；知识点关联年级，数学题可以关联多个知识点并指定一个主要知识点。
- 数学题题干和单选题选项都只支持纯文本、换行和常用数学 Unicode 符号，不支持图片、HTML、Markdown 或 LaTeX；分数使用 `1/2` 形式，竖式使用结构化题型。
- 数学题可以配置可选答案解析和简单、中等、困难三级难度。
- 数学题状态为草稿、已启用或已停用；只有已启用题目进入抽题范围，历史题目不物理删除。
- 数学题一旦被任何答题轮次使用，题干、选项和正确答案不可修改；修正时停用旧题并新增数学题，不保存题目版本快照。
- 会员选择年级后，系统从该年级已启用的数学题中随机抽取 10 道不重复题目形成答题轮次，不建立固定试卷或试卷管理模块。
- 抽题优先选择会员从未答过的题；不足时复用会员以前答过且最久未出现的题，同一轮不重复。年级少于 10 道不同的已启用题时不能开放答题。
- 每轮默认抽取 4 道简单题、4 道中等题和 2 道困难题；某个难度题量不足时由其他难度补齐。
- 一期支持单选题、判断题、数字填空题、算式输入题和竖式计算题，并提供错题本和收藏能力；系统中不存在积分概念。
- 算式输入题和竖式计算题是两个结构化题型，共用移动应用内的数学键盘。
- 数学键盘包含 `0-9`、`+`、`-`、`×`、`÷`、`>`、`<`、`=`、小数点、删除、清空和确认；分数与括号使用专门输入控件。
- 算式输入题允许配置多个可接受答案，使用安全的表达式解析与规范化逻辑判分，不执行会员输入的代码。
- 数字填空题默认按数学值判断等价，例如 `0.5`、`0.50` 和 `1/2` 相等；管理员可以为具体题目要求指定答案格式。
- 竖式计算题保存按数位对齐的完整过程结构，但一期只按最终结果判定整题是否获得 10 分，不进行部分给分。
- 每个答题轮次中每道题 10 分，由系统自动评分，满分为 100 分；获得 100 分时移动应用展示奖品信息。
- 答题轮次由服务端保存；会员逐题提交答案但不立即看到对错，中途退出后可以恢复唯一一个进行中的轮次。
- 进行中轮次可以主动放弃，持续 7 天未完成则自动转为已放弃；已放弃轮次不评分、不生成报告、不进入错题本且不给奖品。
- 一期不增加 Worker 或定时任务；API 在会员查询、继续或开始答题时，根据 `expiresAt` 在事务内将过期轮次转为已放弃。
- 完成 10 道题后统一生成答题报告，展示总分、错题、正确答案和可用的答案解析。
- 第 10 题提交时，API 在同一个数据库事务中锁定轮次、判分、生成报告、更新错题本并创建获奖记录；任一步失败则全部回滚。
- 移动端写操作使用请求幂等编号，重点覆盖逐题提交、第 10 题结算和收藏操作；重试不得重复记录答案、报告或获奖记录。
- 奖品是系统管理员线下购买的实物；系统管理员在管理后台添加奖品信息，系统本身不负责购买奖品。
- 奖品信息只包含文字，不展示或上传奖品图片。
- 奖品字段包括名称、说明、线下领取说明、启用状态和适用年级，不包含价格、库存、地址或物流字段。
- 每个开放答题的年级必须配置一个当前奖品；完成第 10 题并确认满分时，按本轮年级当时的当前奖品创建获奖记录。
- 每个满分轮次都产生不可修改的获奖记录，关联会员、答题轮次、奖品和获奖时间；允许同一会员重复获得同一个奖品。
- 系统不管理奖品库存、地址、物流或领取状态，只展示奖品信息和线下领取说明；购买与交付全部在线下完成。
- 移动应用可以查看每一次答题报告。
- 一期不加入拍照搜题、AI、支付、完整离线或实时对战。
- 系统管理员是唯一后台角色并拥有全部权限；答题记录只允许查看，不允许修改或删除。
- 系统保留不可修改的管理员审计记录，覆盖管理员登录、会员启用/停用、年级、知识点、题目和当前奖品的变更；审计内容不记录密码、令牌或完整手机号。

## 域名与入口

- 管理后台和 API 使用同一根域名下的不同子域名。
- 裸域名预留给官网或应用下载引导页。
- 正式环境使用 `admin.<根域名>` 和 `api.<根域名>`。
- 云服务器使用 Nginx 统一处理 HTTPS 和反向代理；管理后台和 API 不直接暴露应用端口。

## 环境

- 本地开发环境：用于开发和测试，应用直接运行，不使用 Docker 部署；本机已安装 Node.js、MySQL 和 Redis。
- 线上生产环境：一期完成后直接部署，使用 Docker 容器，不设置独立的云端测试环境。
- 本地环境不得直接使用线上生产数据库。
- 本地 MySQL 应与项目目标 MySQL 8.4 主版本一致。

## 生产网络与发布

- 一期生产只使用一台 ECS，接受发布时短暂停机，不增加负载均衡、Kubernetes 或多机高可用；API 保持无状态，业务状态落到 RDS，便于后续水平扩展。
- ECS 与 RDS 应处于同一地域、同一 VPC；API 通过 RDS 内网地址连接。
- RDS 不开放公网连接，白名单只允许 ECS 内网 IP 或对应安全组。
- ECS 使用 Docker Compose 运行 `nginx`、`admin` 和 `api` 三个容器；RDS 不进入 Compose，一期没有 Redis、Worker 或 OSS 容器。
- 管理后台与 API 镜像保存到与 ECS 同地域的阿里云 ACR 企业基础版，分别使用独立镜像仓库。
- 管理后台与 API 分别构建带 Git 提交号标签的 Docker 镜像，不以 `latest` 作为唯一可部署版本。
- 代码推送后可以自动检查、测试、构建并推送镜像，但生产部署必须人工确认，禁止每次推送直接更新线上。
- 发布顺序为：检查与测试、构建镜像、推送 ACR、人工确认、ECS 拉取、执行 Prisma 迁移、更新容器、健康检查。
- 发布后执行健康检查并保留上一版本镜像；失败时切回上一版本。
- 数据库迁移必须与上一应用版本兼容，执行风险变更前确认 RDS 备份可用。
- APP 上架前清理线上测试会员及其答题数据。

## 持续集成与发布

- Gitee 作为代码远端，阿里云云效 Flow 作为持续集成与发布平台，并连接 ACR 和 ECS。
- 流水线 YAML 保存在仓库中；普通代码推送只自动检查、测试、构建和推送镜像，生产部署必须经过人工审批。
- 默认分支使用 `main` 并启用保护规则；功能分支通过合并进入 `main`，禁止直接强制推送。
- 生产镜像只从 `main` 上的版本标签构建，并使用对应 Git 提交号作为镜像标签。
- CI 使用临时 API、管理后台和独立测试 MySQL 验证，不连接生产 RDS，也不建立长期云端测试环境。
- 移动应用在本地模拟器或真机连接本地 API 验证；应用商店内测阶段使用线上 API 和专用测试账号。
- 移动应用使用 EAS Build 生成 Android/iOS 安装包，生产构建与应用商店提交必须手动触发。

## 测试策略

- API、共享包和管理后台单元测试使用 Vitest。
- API 数据库集成测试使用 Vitest 和独立测试 MySQL。
- 管理后台关键流程使用 Playwright。
- Expo 移动应用组件测试使用 Jest 和 React Native Testing Library，关键移动流程使用 Maestro。
- 移动应用至少在一组手机紧凑尺寸、平板竖屏和平板横屏下验证登录、作答、数学键盘、竖式输入和报告展示。
- 核心测试覆盖数学表达式与等价答案、竖式判分、抽题比例与不重复、轮次恢复/放弃/过期、第 10 题事务与重复提交、满分获奖、题目不可变、身份隔离和统一 API 响应。
- CI 依次执行冻结锁文件安装、格式与 Lint、类型检查、单元测试、MySQL 集成测试、管理后台 E2E、Prisma schema/迁移检查以及 admin/api 生产构建；任一步失败都不能产生可部署镜像。

## 生产密钥

- 生产环境变量保存在 ECS 的受限配置文件中，只允许部署用户读取。
- 密钥不提交 Git、不写入 Docker 镜像且不输出到日志。
- 数据库凭据、会话签名密钥和管理员初始化密钥彼此独立。
- API 使用独立的最小权限 RDS 应用账号，不使用 RDS 管理账号运行应用。

## 日志与健康检查

- API 输出结构化 JSON 日志到标准输出，包含时间、级别、请求编号、路径、HTTP 状态、耗时、主体内部编号和错误码。
- 日志禁止记录密码、令牌、完整手机号和完整答题内容。
- Docker 开启日志文件大小及保留数量轮转，Nginx 分别保留访问日志和错误日志。
- API 提供 `/health/live` 进程存活检查和 `/health/ready` 就绪检查；就绪检查验证 RDS 可用性，但不返回数据库地址、版本或其他敏感配置。

## 登录防刷

- Nginx 按客户端 IP 限制会员和管理员登录请求频率。
- API 使用 MySQL 保存连续登录失败次数和暂停截止时间，一期不为此引入 Redis。
- 会员连续失败 5 次后暂停登录 15 分钟；管理员登录采用更严格的独立限制。
- 登录失败统一提示账号标识或密码错误，不泄露账号是否存在、已停用或处于暂停状态。
