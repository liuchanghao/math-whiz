# 生产镜像进入 ACR 并经人工批准部署

Gitee 代码通过仓库内的云效 Flow YAML 执行检查、测试和构建，管理后台与 API 随后以 Git 提交号为标签推送到同地域阿里云 ACR 企业基础版；自动流程可以构建并推送镜像，但生产部署必须人工确认，ECS 才能拉取明确版本、执行已提交的 Prisma 迁移、更新 Compose 服务并运行健康检查。移动应用则使用 EAS Build，生产构建和应用商店提交也必须手动触发。该方案增加了 ACR、云效和 EAS 的服务依赖及发布凭据管理，但避免在生产 ECS 上临时构建、依赖不可追踪的 `latest` 标签或因代码推送直接触发线上变更，并保留明确的镜像回退点。
